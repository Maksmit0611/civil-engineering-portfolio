# NISARVA — Agent development instructions

## Identity
Product: **NISARVA**
Description: Sanskrit-inspired Australian Engineering Carbon Intelligence AI Agent for lifecycle assessment, embodied carbon calculations, emissions-factor traceability, regulatory references and sustainable civil infrastructure.
Tagline: **Engineering Intelligence, Inspired by Nature.**
Etymology: Coined brand inspired by *Nisarga* (nature), not an exact classical Sanskrit word.

## Engineering and data safety
- Do not invent emission factors, standards text, licences, calculator results, validation status or source references.
- Treat provided 2026 source registry and example factors as acquisition leads, not an approved production database.
- Obtain original official files, record provenance, apply mapping, verify units, factor boundaries, versions and compliance relevance.
- Distinguish lifecycle stages from GHG reporting scopes. Keep lifecycle module D benefits separate and avoid double counting.
- Do not reproduce restricted Standards Australia material or paid datasets without licence.
- Keep traceable source documentation and flag limitations requiring engineer review.

## Freebuff instructions
Start with `README.md`, `FREEBUFF_HANDOFF.md`, `config/source_registry.json`, and `reports/ACQUISITION_AND_LICENSING_REPORT.md`.
Run tests before data ingestion. Follow the documented acquisition and validation process, without portraying partial work as complete.
In newly created code, user interfaces, reports, readmes and examples, use the product name **NISARVA**.
Do not rename or rebrand unrelated projects elsewhere in `civil-engineering-portfolio`.
